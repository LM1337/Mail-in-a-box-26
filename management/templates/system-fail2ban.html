Intrusion Protection

fail2ban watches the logs of this box and bans IP addresses that fail to log in too often. On top of Mail-in-a-Box’s own rules (20 failures within 30 seconds, banned for 10 minutes), repeat offenders get longer bans each time, slow jails catch attacks that try only a few passwords per hour, and addresses on the allowlist are never banned.

“Unban” releases the address in all jails, recidive included, and deletes its ban history, so a new ban starts again at the initial ban time. “in this jail only” releases only that jail’s ban. Failures that other jails counted but did not ban yet stay counted: if a device keeps getting banned, fix its password or put its network on the allowlist below.

Settings

Each new ban of an address lasts twice as long as its previous one, counted over all jails, up to the maximum ban time. fail2ban keeps the ban history for the memory period, also across restarts.

Additional jails with a long window for SMTP AUTH, IMAP/POP3/ManageSieve, Roundcube, Nextcloud and this control panel. The mail jails block only the mail ports, so webmail stays reachable for a banned address.

Durations are in seconds, or with a unit: 30m, 6h, 2d, 1w. With adaptive banning and the slow jails off and an empty allowlist, fail2ban runs exactly with Mail-in-a-Box’s original configuration.
