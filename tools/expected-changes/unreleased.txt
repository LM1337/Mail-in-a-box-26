# Expected changes of an update to the release after v78-r2604.4, for
# tools/update-check.sh after: what this release changes in the recorded
# state. "after" uses this list (with any.txt) when the checkout after the
# update is not at a release tag (bootstrap.sh with TAG=<branch or commit>),
# or when the version after the update has no list of its own. When the
# release is tagged, rename this file to <version>.txt and start a new,
# empty unreleased.txt. The format is in any.txt.
status.txt + ^(✖|\?) +(\S+: )?(This domain's DNSSEC DS record is (not set|incorrect)|DNSSEC 'DS' record set at registrar is valid|The DNSSEC 'DS' record for \S+ is incorrect) # B179: the DNSSEC messages say where the DS records are (below the message, in the control panel under "show more") instead of "see below"
status.txt + ^\? +(\S+: )?Could not determine whether the domain \S+ is blacklisted by dbl\.spamhaus\.org: its name is too long # B181: a mail domain too long for the DBL lookup gets this warning; before, the lookup ended the status check run with a traceback
status.txt + ^\? +(\S+: )?Could not check this domain's DNSSEC DS record: the DNS lookup (timed out|failed) # B182: a DS lookup that timed out or failed gives this warning instead of "This domain's DNSSEC DS record is not set"
dropins.txt + ^/etc/systemd/system/spamassassin-maintenance\.service\.d/mailinabox-spampd-record\.conf # setup restarts spampd only on a change: drop-in that lets spamassassin-maintenance.service write spampd's restart record after sa-update (hook spampd-record)
crontabs.txt + ^/etc/cron\.d/mailinabox-auth-guard [0-9a-f]+$ # B126: the cron job of management/auth_guard.py (every 10 minutes) mails the accounts that Dovecot refuses for logins from the box itself after 30 different wrong passwords in 30 minutes
crontabs.txt + ^/etc/cron\.d/mailinabox-send-limit [0-9a-f]+$ # B221: the cron job of management/send_limit.py (every 5 minutes) mails the minutes in which the sending limit of the box made outgoing mail wait
units.txt + ^miab-sendlimit enabled active$ # B221: the milter of the sending limit (conf/send-limit/milter.py, conf/miab-sendlimit.service)
listening.txt + ^tcp 127\.0\.0\.1:8895 python3$ # B221: the milter of the sending limit listens on 127.0.0.1:8895
postconf.txt - ^non_smtpd_milters = \$smtpd_milters$ # B221: mail through sendmail also passes the milter of the sending limit (setup/dkim.sh), see the next line
postconf.txt + ^non_smtpd_milters = \$smtpd_milters inet:127\.0\.0\.1:8895$ # B221: see the line above
